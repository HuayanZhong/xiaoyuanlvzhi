# 管理端产品规格

本文定义管理端首版页面、输入项、操作、状态变化和验收结果，供产品原型和前端页面设计使用。首版采用单一“管理员”角色；管理员账号由项目负责人预先配置。下文中“首版建议”是为了让页面可以先做出来的产品默认值，涉及学校制度的数值仍做成可配置项。

## 1. 导航与全局交互

### 1.1 侧边导航

管理端使用顶部一级分组 + 左侧二级菜单。分组只用于导航组织，不改变各业务模块的职责。

```text
  养护审核
  环保任务
  问题反馈
资源
  品种档案

  奖励商品
  兑换订单
用户

  资讯管理

  数据统计
```

| -------- | -------------- | ------------------- |
| 运营     | 工作台         | `/dashboard`        |
| 运营     | 领养管理       | `/adoptions`        |

### 1.2 全局页面规则

- 列表默认按创建时间倒序，每页 10 条；支持上一页、下一页和总数显示。
- 筛选区提供“查询”和“重置”。更改筛选条件后，点“查询”才刷新结果；重置恢复默认筛选。
- 表单内必填项显示星号；提交失败时在字段旁显示中文原因，并保留已填写内容。
- 所有驳回、取消、结束、禁用和积分调整操作都要二次确认；需要原因的操作必须填写原因。
- 状态使用固定文案，不只用颜色区分。详情页展示创建时间、最近处理时间、处理人和操作记录。
- 空列表显示空状态及可执行的下一步；加载失败显示重试入口；无权限时隐藏操作按钮并显示只读内容。

### 1.3 后台壳与主题

- 登录后的所有业务页面使用统一后台壳：顶部一级分组、左侧二级菜单、内容区；登录页不显示后台壳。
- 视口宽度小于 992px 时，顶部一级菜单和左侧菜单收起为抽屉导航，页面不产生横向滚动。
- 品牌区使用纯文字字标：产品名加“管理后台”，不使用图形图标。
- 内容区四周留白统一为 24px；页面卡片铺满内容区，不设固定最大宽度。
- 顶栏的折叠、主题和账号操作使用虚线图标按钮；主题切换后刷新仍保留选择。
- 颜色使用 antd 默认主题，不注入自定义品牌主色或强调色；亮色和暗色模式下文字与控件都要保持可读。

## 2. 工作台

**目标：** 管理员进入系统后先看到待办，并可直接进入对应处理页。

### 页面区块

| 区块           | 展示内容                                 | 点击行为                     |
| -------------- | ---------------------------------------- | ---------------------------- |
| 待审核领养     | 状态为“待审核”的申请数                   | 打开领养管理并默认筛选待审核 |
| 待审核打卡     | 状态为“待审核”的打卡数                   | 打开养护审核并默认筛选待审核 |
| 待审核任务     | 状态为“待审核”的任务凭证数               | 打开环保任务审核列表         |
| 待领取奖励     | 状态为“待领取”的兑换订单数               | 打开兑换订单并默认筛选待领取 |
| 待处理领养变更 | 状态为“取消审核中”或“归还审核中”的申请数 | 打开领养管理并筛选待处理变更 |
| 可领养绿植     | 当前状态为“可领养”的单株数               | 打开单株库存并筛选可领养     |
| 在养绿植       | 当前状态为“养护中”的单株数               | 打开单株库存并筛选养护中     |

页面下方展示最近待处理记录：业务类型、学生、提交时间、当前状态和“去处理”。没有待办时显示“当前没有待处理事项”。工作台指标均由业务记录实时汇总，首版不允许管理员手工改数字。

**验收：** 任一待办卡片点击后，列表筛选正确；处理完成返回工作台后，待办数更新；无待办时页面仍展示绿植和活动基础概况。

## 3. 绿植资源

### 3.1 品种档案

**列表列：** 品种名称、封面、养护难度、养护说明摘要、关联单株数、启用状态、更新时间、操作。

**筛选：** 品种名称关键词、启用状态。

**新增/编辑字段：**

| 字段     | 规则                                                         |
| -------- | ------------------------------------------------------------ |
| 品种名称 | 必填，1–40 字，同名不允许重复                                |
| 封面图片 | 可选；首版建议最多 1 张                                      |
| 养护难度 | 必填，简单/一般/较难三档                                     |
| 光照说明 | 必填，最多 200 字                                            |
| 浇水说明 | 必填，最多 200 字                                            |
| 养护间隔 | 必填正整数，单位为天；作为打卡频率提示，不自动替代管理员审核 |
| 其他说明 | 可选，最多 500 字                                            |
| 启用状态 | 启用/停用；停用后不能用于新领养，历史档案保留                |

**操作：** 新增、编辑、启用、停用、查看关联单株。已有单株关联的品种不能删除；停用品种不影响在养学生查看原养护说明。

### 3.2 单株库存

**列表列：** 单株编号、品种、摆放位置、当前状态、当前领养学生、加入时间、最近更新时间、操作。

**筛选：** 单株编号/学生关键词、品种、位置、状态。

**新增/编辑字段：**

| 字段     | 规则                                           |
| -------- | ---------------------------------------------- |
| 单株编号 | 必填，全系统唯一；创建后不允许修改             |
| 关联品种 | 必填，只能选择启用品种                         |
| 展示名称 | 可选，最多 40 字；无名称时展示品种名和单株编号 |
| 校园位置 | 必填，最多 100 字                              |
| 图片     | 可选；首版建议最多 3 张                        |
| 备注     | 可选，最多 300 字                              |

**单株状态：** 可领养、待领取、养护中、维护中、已停用。新增单株默认“可领养”。状态由领养、交接、归还和维护操作驱动，不提供任意状态下拉框。

**操作：** 新增、编辑位置/展示信息、送修、维护完成、停用。维护中单株不能被领养申请绑定；养护中的单株不能直接送回可领养，必须先结束领养并确认实物归还。已产生领养记录的单株只能停用，不能删除。

**验收：** 两条单株记录不能使用相同编号；待领取、养护中、维护中的单株不会显示在可领养库存中；列表状态与领养详情状态一致。

## 4. 领养管理

### 4.1 申请列表

**状态：** 待审核、已驳回、待领取、取消审核中、养护中、归还审核中、已结束、已取消。

**筛选：** 申请编号/学生姓名/学号、状态、品种偏好、提交日期范围。

**列表列：** 申请编号、学生、学号、品种偏好、申请时间、当前状态、处理人、操作。

**详情显示：** 学生资料、申请备注、申请时间、选定的单株、审核意见、交接时间、归还结果、完整状态时间线。

### 4.2 审核申请

- 点“通过”打开选株弹窗，只列出状态为“可领养”的单株；管理员选择一株并确认。
- 确认后，申请变为“待领取”，该单株变为“待领取”，其他管理员不能再把它分配给别的申请。
- 点“驳回”打开原因弹窗；原因必填，5–200 字。确认后申请变为“已驳回”，学生收到原因。
- 学生可在驳回后修改申请并重新提交；每次重提保留原申请的处理记录。

### 4.3 线下交接与结束领养

- “待领取”详情提供“确认已交接”。管理员在线下交付实物后点击并确认；申请转为“养护中”，单株转为“养护中”。
- 学生提交归还申请后，详情进入“归还审核中”；管理员确认已收到实物，并选择“可再次领养”或“转入维护”。
- 确认归还后，关系变为“已结束”；单株按所选结果变为“可领养”或“维护中”。
- 驳回归还申请必须填写原因；关系恢复“养护中”，学生收到原因。
- 学生对“待领取”申请发起取消后，详情进入“取消审核中”；管理员确认取消后变为“已取消”并释放单株，拒绝后恢复“待领取”并填写原因。
- “待领取”超过可配置领取期限后自动变为“已取消”，释放单株。首版建议默认期限为 7 个自然日。

**验收：** 申请通过必定绑定一株当前可领养的单株；未确认交接前学生看不到“养护中”；确认归还前库存不能重新开放；同一申请不能重复审核或重复释放单株。

## 5. 养护审核

### 列表与详情

**筛选：** 学生/学号/单株编号、品种、审核状态、提交日期范围。

**列表列：** 打卡编号、学生、单株、提交时间、说明摘要、状态、待发积分、操作。

详情展示打卡说明、照片、学生、单株养护说明、上次打卡时间及操作记录。图片可放大查看。

### 审核操作

- “通过”：确认后状态变为“已通过”；按当前有效积分规则生成一条积分流水；重复点击不重复发分。
- “驳回”：必须填写 5–200 字原因；状态变为“已驳回”，通知学生。学生可修改并重新提交，旧记录保留。
- 审核完成后操作按钮禁用；管理员可查看记录，不能改写已通过结果。需要纠错时走“积分调整”，写明原因并产生新流水。

### 养护规则

养护间隔和每次通过可得积分在品种档案/积分规则中配置。学生只能在上次有效打卡达到养护间隔后提交；间隔内再次提交时展示下一次可打卡日期。未配置积分规则时，管理员不能通过打卡；页面提示先配置规则，仍可驳回并说明原因。

**验收：** 审核通过后学生端状态与积分明细同步；驳回后可见原因和重提入口；重复审核、重复提交不会多发积分。

## 6. 环保任务

### 6.1 任务列表与配置

**列表列：** 任务标题、开放时间、报名人数/上限、通过人数、单人积分、状态、操作。

**筛选：** 标题关键词、草稿/未开始/进行中/已结束/已停用、开放时间。

**新建/编辑字段：**

| 字段               | 规则                                                   |
| ------------------ | ------------------------------------------------------ |
| 标题               | 必填，1–60 字                                          |
| 封面               | 可选，最多 1 张                                        |
| 任务说明           | 必填，最多 2000 字，说明完成标准和安全要求             |
| 开始时间、结束时间 | 必填；结束时间必须晚于开始时间                         |
| 参与人数上限       | 可选正整数；为空表示不限；已报名人数达到上限后停止报名 |
| 凭证要求           | 至少选文字说明或图片；文字最多 500 字，图片最多 3 张   |
| 每人奖励积分       | 必填正整数；发布后不可修改                             |
| 发布状态           | 保存草稿或立即发布                                     |

发布后可编辑说明和封面；若已有报名，不允许修改时间、人数上限和奖励积分。需要调整这些规则时，停用旧任务并复制创建新任务，避免已报名学生规则变化。

### 6.2 报名与凭证审核

学生在开放时间内报名；名额满或任务未开放时不能报名。同一学生同一任务只生成一条参与记录。学生提交凭证后进入“待审核”。

**审核列表列：** 任务、学生、报名时间、提交时间、凭证摘要、审核状态、奖励积分、操作。

- 通过：状态为“已通过”，生成该任务对应积分流水。
- 驳回：原因必填 5–200 字；学生可重新提交，记录每次提交和审核历史。
- 任务结束后仍可处理截止前已提交的凭证；结束后不能新增报名或提交。

**验收：** 满额后无法继续报名；任务规则不会因编辑追溯改变；同一参与记录最多获得一次有效奖励积分。

## 7. 积分与奖励

### 7.1 积分规则与流水

规则列表列：行为来源、积分数、频率限制、启用状态、生效时间。编辑字段包括行为来源、每次积分（正整数）、限制次数、限制周期（每日/每周/每任务）和启用状态。首版内置养护打卡和环保任务两种来源；资讯积分默认关闭，待明确行为规则后再开启。新规则只影响生效后的行为，不追溯修改历史流水。

流水列表列：流水号、学生、来源业务、来源编号、变动积分、变动后余额、操作人、时间、备注。筛选学生、来源、正向/冲正和日期。

人工调整表单：学生、增减方向、整数积分、必填原因 5–200 字、调整前后余额预览。提交前二次确认；扣减不得使余额低于 0；调整只新增流水，不编辑历史流水。

### 7.2 奖励商品

**列表列：** 商品名称、兑换积分、库存、领取地点、状态、操作。

**编辑字段：** 名称必填 1–60 字；说明最多 500 字；图片最多 3 张；兑换积分为正整数；库存为非负整数；领取地点必填；领取期限为正整数天，默认 7 天；上架/下架状态。

下架只阻止新兑换，不改变已有订单。库存不足或商品下架时，学生端不可兑换。库存减少不得小于已占用订单数。

### 7.3 兑换订单

**状态：** 待领取、已领取、已取消、已超时。

列表列：订单号、学生、商品、兑换积分、下单时间、领取截止时间、状态、操作。

- “确认领取”：管理员核对学生和商品后确认；订单变为已领取，已占用库存转为实际消耗。
- “取消订单”：仅待领取可操作，必须填写原因；一次性退还积分并释放库存。
- 超过领取截止时间仍未领取的订单自动变为已超时，执行同样的积分退还和库存释放。
- 领取完成后不能取消或退回积分；如需人工纠错，新增积分调整流水并记录原因。

**验收：** 提交兑换时积分余额足够且库存大于 0；成功后积分和可用库存同时更新；取消/超时只恢复一次；并发兑换不能产生负库存或负积分。

## 8. 学生管理

**列表列：** 姓名、学号、院系、班级、手机号、当前积分、在养绿植数、账号状态、注册时间。

**筛选：** 姓名/学号、院系、账号状态、注册日期。

详情页展示基础资料、领养记录、打卡记录、任务记录、积分流水和兑换订单。管理员可启用或禁用账号；禁用后学生不能新建申请、报名、打卡或兑换，历史记录和待履约订单保留。管理员不能删除已有业务记录的学生。

**验收：** 禁用操作有确认和原因；学生端明确显示账号受限；重新启用后历史数据恢复可见。

## 9. 资讯管理

**列表列：** 标题、分类、作者、状态、发布时间、更新时间。

**编辑字段：** 标题必填 1–80 字；分类必选；摘要最多 200 字；封面可选；正文必填；保存草稿/发布/撤回。

发布后的资讯可编辑正文并记录更新时间；撤回后学生端不可新查看，但历史阅读记录保留。首版资讯不自动发积分。

## 10. 问题反馈

**列表列：** 反馈编号、学生、问题类型、关联业务、提交时间、处理状态、操作。

**状态：** 待处理、处理中、已回复、已关闭。管理员打开详情查看描述、照片和关联记录；可以填写回复（5–500 字）并标为“已回复”。学生看到回复后可确认关闭；管理员也可关闭已解决记录并填写结论。处理过程保留时间线。

**验收：** 学生提交反馈后管理员工作台出现待办；管理员回复后学生收到通知并能在反馈详情查看；关闭后仍可查询历史。

## 11. 数据统计

提供日期范围筛选，默认最近 30 天；图表下方显示明确的指标名称和计算口径。

| 指标         | 计算口径                                                                     |
| ------------ | ---------------------------------------------------------------------------- |
| 当前在养数   | 统计时单株状态为“养护中”的数量                                               |
| 累计领养数   | 所选时间内进入“养护中”的领养关系数                                           |
| 参与学生数   | 所选时间内至少有一条通过审核的打卡或任务凭证的去重学生数                     |
| 任务完成率   | 已通过人数 ÷ 已报名且任务已结束的参与人数；分母为 0 时显示“—”                |
| 当前积分排行 | 按当前积分余额倒序，默认显示前 10 名                                         |

## 12. 关键验收流程

1. 管理员新建品种和单株后，学生能看到可领养数量；管理员停用单株后，学生不能申请该单株。
2. 管理员审核通过申请并选中单株后，库存变为待领取；确认交接后，学生看到自己的在养绿植。
3. 学生提交打卡，管理员通过后只产生一笔积分；驳回后学生看到原因并能重新提交。
4. 管理员发布任务，学生报名并提交凭证；通过后积分到账，任务结束后不再允许新报名。
5. 学生兑换奖励后积分和库存同步占用；管理员确认领取后订单完成；取消或超时后积分和库存各恢复一次。
6. 学生申请归还后，管理员确认实物状态；单株按可再次领养或维护进入对应库存状态。
