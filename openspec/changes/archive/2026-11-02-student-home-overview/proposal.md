# Proposal

## Why

学生首页目前只展示在养数量、积分余额和消息入口，缺少产品规格要求的待处理事项、可报名环保任务和养护提醒。学生要确认“有没有待审核的打卡、有没有被驳回需要重提、有没有奖励待领取、哪株绿植该打卡了”，必须分别进入我的绿植、领养、任务和订单页面逐一查找。

补齐首页六区块后，首页才能承担“当前状态、下一步操作”的入口职责，也让已有的通知、打卡、任务和兑换数据在首屏形成闭环。

## What Changes

- 首页整理为六个区块：我的绿植、待处理事项、当前积分、环保任务、养护提醒、消息；桌面两列、移动端单列，保留现有档案条。
- 新增“待处理事项”：按打卡待审核、领养/养护/任务驳回待重提、奖励待领取分类显示数量，每行直接进入该分类最近的一条记录；无记录的分类不显示。
- 新增“环保任务”：展示最多 3 个当前可报名任务（进行中、未参与、未满额），进入任务详情；没有可报名任务时提供任务列表入口。
- 新增“养护提醒”：展示最多 3 株已到打卡时间的绿植，进入对应养护页；没有到期植株时显示空态。
- 待处理事项、环保任务和养护提醒使用独立的 `home-overview` 取数并行加载；每个区块独立失败并提供重试，不影响资料、积分和消息。
- 不新增路由，不修改 Spring 接口，不修改 admin 或共享包。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `web-shell`: 新增首页待处理事项、首页环保任务、首页养护提醒和首页区块容错四条需求；现有“首页摘要”保持覆盖我的绿植、当前积分和消息入口。

## Impact

- 受影响应用：`apps/web`（首页改版，新增 `app/utils/home-overview.ts` 与首页测试）。
- 接口：只消费现有的 `GET /care/checkins`、`GET /adoptions`、`GET /tasks/participations`、`GET /rewards/orders`、`GET /tasks`、`GET /care/eligible-plants`；Spring 无需改动。
- 认证：沿用现有学生 Cookie 与路由守卫，不新增受保护路径。
- 依赖与工具链：不新增依赖，继续使用现有设计 token、`FolioSection` 与状态映射。
