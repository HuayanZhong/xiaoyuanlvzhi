# Proposal

## Why

养护审核和环保任务已经能在通过后发放积分，但管理端仍没有积分规则、全量流水和人工调整入口。规则种子为 0 分且停用，管理员只能在接口或数据库层配置；积分发放后也无法在页面核对、筛选或纠错。继续做奖励商品和兑换订单前，需要先把积分账本的配置、审计和纠错闭环补齐。

## What Changes

- 将 `/points/rules` 从占位页替换为“积分规则与流水”页面，使用“积分规则”和“积分流水”两个 tab。
- 积分规则：展示 `CARE_CHECKIN` 和 `ECO_TASK` 两条规则；支持修改积分、频控次数、频控周期和启用状态。`CARE_CHECKIN` 规则积分优先于品种积分；`ECO_TASK` 规则只控制启停和日/周频控，任务积分仍以任务的每人奖励积分为准。
- 积分流水：展示全部学生的积分变动，包含学生、来源、变动积分、变动后余额、操作人、时间和原因；支持按学生、来源、正负方向和日期筛选，以及每页 10 条分页。
- 人工调整：管理员可选择学生、增加或扣减整数积分、填写 5–200 字原因，并在提交前预览调整前后余额；余额不足时拒绝扣减。
- 加固 Spring 积分接口：人工调整只能作用于学生账号；调整请求支持幂等键，重复提交不重复写流水；原因按去除首尾空白后的长度校验；频控周期首版只保留不限、每日和每周。
- **BREAKING（管理端积分规则 API）**：`PER_TASK` 不再作为可配置频控周期，服务端返回 400 `FREQUENCY_PERIOD_INVALID`。当前 admin 尚未接入该接口，影响仅限直接调用 `PUT /api/v1/admin/points/rules/{sourceType}` 的客户端。
- 不新增路由或导航项，不实现奖励商品、兑换订单、学生管理、工作台、数据统计或资讯管理。

## Capabilities

### New Capabilities

- `admin-points`: 管理端积分规则配置、全量积分流水查询和人工积分调整行为。

### Modified Capabilities

- 无。养护积分来源和任务积分来源的既有规格保持不变；本变更只提供管理端入口并加固积分接口。

## Impact

- `apps/admin`：新增 `/points/rules` 页面、积分 API 层、页面测试和路由测试；README 更新模块状态。
- Spring 后端：修改管理端积分规则与人工调整接口的校验和幂等行为，补充服务测试与接口契约测试；预期不需要数据库结构迁移。
- 文档：同步更新 `docs/product/admin.md`、`docs/product/business-rules.md` 和 `backend/docs/api.md` 中关于 `ECO_TASK` 规则、频控周期和人工调整的说明。
- 不新增依赖，不修改认证和角色边界，不修改共享包，不修改数据库表结构。
