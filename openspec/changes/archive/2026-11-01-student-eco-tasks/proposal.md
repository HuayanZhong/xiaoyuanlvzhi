# Proposal

## Why

学生端已经能领养绿植并提交养护打卡，但「环保任务」这一条参与、审核、积分来源完全缺失：管理员可以在管理端配置和审核任务，学生却看不到任务、无法报名，也无法提交完成凭证。这既让管理端的任务审核没有入口，也让积分只剩养护一个来源。补齐后，学生端的「首页、绿植、任务、积分、我的」才走完第一半，任务审核产生的积分也有据可查。

## What Changes

- 新增学生任务列表 `/tasks`：只展示已发布任务，可按全部、可报名、已参加、已结束筛选；每项显示标题、开放时间、剩余名额、单人奖励积分与状态。
- 新增任务详情 `/tasks/[id]`：展示任务说明、完成标准与凭证要求、时间、名额、奖励积分；在开放时间内可报名；参与记录的状态、凭证版本、驳回原因和重提表单都内嵌在同一页。
- 主导航新增「任务」入口，桌面横向导航和窄屏底部导航同时生效，位置在「绿植」之后；`/tasks` 前缀纳入未登录重定向。
- 不修改 Spring 接口。复用已有的 `GET /api/v1/tasks`、`GET /api/v1/tasks/{id}`、`POST /api/v1/tasks/{id}/join`、`GET /api/v1/tasks/participations` 和 `POST /api/v1/tasks/participations/{id}/submissions`。
- 首页本次不新增任务区块，现有两个区块保持不变。
- 凭证图片复用现有上传、本机预览和私有图片读取能力，不新增上传接口或依赖。

不属于本次范围：任务积分规则配置、通知、首页待办与提醒、任务参与记录的独立路由、管理端页面。

## Capabilities

### New Capabilities

- `student-tasks`: 学生查看已发布环保任务、按状态筛选、报名参加、提交与重新提交任务凭证，并查看参与状态、审核结果与凭证历史。

### Modified Capabilities

- `web-shell`: 主导航增加「任务」入口，路由清单增加 `/tasks` 与 `/tasks/{id}`，登录保护前缀增加 `/tasks`。

## Impact

- 受影响应用：仅 `apps/web`。
- 不修改 Spring 接口、认证流程、持久化结构或共享包；不涉及 `@repo/http-client`、`@repo/env`、`admin` 或环境变量。
- 不新增运行时依赖，仍使用纯 CSS token 与现有 Nuxt/Vitest 约定。
- 现有导航测试、页面壳测试和受保护路径测试需要随新增入口和路由同步更新；首页与「我的」页面行为不变。
